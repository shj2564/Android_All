# 5008 미러 진단 0.3 — 하향·원위치 복귀 확인 / 사용 안내

2019 Peugeot 5008 GT / CMZX / Reglink / Raise PSA 조사용 앱입니다.
0.2는 사용자 휴대폰에서 설치·샘플 실행, 차량 올인원에서 서비스 및 CAN 정보 조회가 확인됐습니다. 0.3에는 실제 미러 하향 설정을 켜고 끄는 시험 화면을 추가했습니다. 2026-09-14 사용자가 0.3의 ON 요청 1회 후 실제 후진 미러 하향 성공을 확인했습니다. 현재 v03을 성공 기준본으로 유지합니다.

## 현재 확인 결과

| 항목 | 확인 상태 |
|---|---|
| ON 1회 실행 후 후진 미러 하향 | 2026-09-14 사용자 실차 확인 |
| 후진 해제 후 원래 각도로 복귀 | 2026-09-14 후속 사용자 확인 |
| 시동을 껐다 다시 켠 뒤 설정 유지 | 아직 미확인. 사용자의 요청으로 유지된다는 가정 아래 후속 사용 방법을 정리함 |
| OFF 실행으로 기능 해제 | 아직 실차 미확인 |

## 평소 사용

성공한 **CMZX-MirrorCheck-v03.apk**를 현재 기준본으로 사용합니다. **재시동 뒤에도 설정이 유지된다는 전제에서는 추가 개발 없이 현재 상태로 사용할 수 있습니다.** 재시동 유지 여부를 확인 완료로 기록한 것은 아닙니다.

v03은 사용자가 누른 ON 설정을 한 번 전달합니다. 후진할 때마다 거울을 움직이는 명령을 보내는 앱은 아닙니다. 설정이 유지되는 동안에는 앱을 열어 두거나 매번 켜기 버튼을 누를 필요가 없습니다. 평소에는 올인원의 홈 화면이나 다른 앱을 사용하면 됩니다.

시험 기록은 **5008 미러 진단 → 실차 미러 설정 시험 → 이전 시험 기록 보기**에서 확인하고, **시험 결과 복사 / 시험 결과 공유**로 보관할 수 있습니다.

성공 APK의 SHA-256: `00e5863447723d93db9301148200939b7cb658f16bd383c5e216983c4bc4daff`. APK와 소스는 실차 성공 당시 그대로 보존했습니다.

## 나중에 설정을 다시 켜야 할 때

다음은 이미 실차에서 성공한 ON 설정을 다시 적용하는 절차입니다. 전원 재인가 후 설정 유실이나 그 복구를 이번에 시험한 것은 아닙니다.

1. 정차·P단·주차브레이크 상태에서 **5008 미러 진단 → 실차 미러 설정 시험**을 엽니다.
2. **1. 차량 연결 확인**을 누릅니다. 성공 당시의 서비스·MCU·제품·CAN 조건과 일치하면 설정 버튼이 활성화됩니다.
3. **2. 미러 하향 켜기 → 켜기 1회 실행**을 한 번 누릅니다.
4. 약 8초간 관찰이 끝나면 전체 결과를 보관하고, 후진 시 하향과 후진 해제 후 원위치 복귀를 확인합니다.

조건 불일치로 설정 버튼이 활성화되지 않으면 **차량 정보 읽기** 결과를 보관해 새 환경을 대조해야 합니다. 서비스나 MCU가 업데이트된 경우에는 기존 성공 기준과 달라질 수 있습니다. 조건 검사를 통과시키기 위해 다른 차종 프로필을 고르는 절차는 사용하지 않습니다.

재시동 후 기능이 유지되지 않는다면, **ON을 다시 누르기 전에 차량 정보 읽기 결과**를 보관하면 설정이 사라진 것인지 대조하는 데 도움이 됩니다. 이 값은 서비스가 보관한 최근 캐시이므로 실제 동작 확인과 함께 해석합니다.

## 설치와 시험 순서

1. `CMZX-MirrorCheck-v03.apk`를 차량 안드로이드 올인원에 설치합니다. 기존 0.2와 패키지 및 서명 키가 같고 versionCode는 3입니다.
2. 정차·P단·주차브레이크 상태에서 **5008 미러 진단 → 실차 미러 설정 시험**을 엽니다.
3. **1. 차량 연결 확인**을 누릅니다. 확인한 서비스·차종·CAN 조건이 맞으면 켜기·끄기 버튼이 활성화됩니다.
4. **2. 미러 하향 켜기 → 켜기 1회 실행**을 누릅니다. 이것은 실제 차량 설정 명령을 1회 시도하는 버튼입니다.
5. 약 8초 동안 수신값 관찰이 끝나면 **시험 결과 복사 / 공유**로 결과를 보냅니다. 화면을 나누어 촬영해도 됩니다.
6. 시동이 켜진 상태에서 브레이크를 유지하고 R단을 선택해 실제 거울이 내려가는지 확인한 뒤 P단으로 돌아옵니다. 작동 여부도 함께 알려주세요.

**미러 하향 끄기**는 같은 설정 항목에 OFF를 보내는 수동 기능입니다. 앱 종료·재부팅 시 자동 켜기, 자동 복원 또는 반복 송신은 하지 않습니다. 앱 삭제만으로 차량 설정이 원래대로 돌아간다고 볼 수 없습니다.

조회 화면의 **차량 정보 읽기**와 **샘플 보기**는 설정을 전송하지 않습니다. 일반 휴대폰에서는 샘플을 볼 수 있으며 실제 시험 조건 검사는 통과하지 않습니다.

## 실차 조건 검사

제어 버튼을 누를 때마다 원본 서비스 APK의 해시·버전, Android API와 하드웨어, 차종·MCU·제품 코드·CAN 정보를 다시 검사합니다. 현재 확인된 조합은 다음과 같습니다.

- 서비스: `260129-1424 / 26012914`, SHA-256 `8c7b9ee385fe2503dd592b6114436235a1e0bcefd8f6c80b6e9a3478b5d074d9`
- Android API 27, `mt6765`
- `psa_5008_2014_2019`, `peugeot`, `psa`, `generic`
- `CMZXR62N-U1`, MCU `95.08@260715`
- `raise`, `raise-psa`, `PSA-RZ-15-0128.212.06-HSE`
- 연결 true / 일시중지 false, 0x38 순수 데이터 9바이트
- 기존 서비스가 계산한 OFF/ON 직렬 프레임이 기준과 동일

읽기용 Binder 허용 목록은 유지됩니다. 설정 시험에서는 별도 경로의 `write(CANBoxPacket)`(4)로 **type 0x80, payload [0x1E, 0 또는 1]**만 전달합니다. 한 번만 사용할 수 있는 요청은 5초 후 만료되고, 중복 실행 및 송신 전 취소를 검사합니다. 원시 송신, 프로필 변경, suspend/resume, 스크립트 교체, FOCAL 설정 변경 기능은 없습니다.

수신 관찰을 위해 callback 등록(1)/해제(2)를 사용합니다. 상태 요청용 CAN 패킷은 추가로 보내지 않으며 8초간 콜백과 최근 캐시를 확인합니다. `write`가 예외 없이 반환되어도 실제 차량 적용을 확인한 것은 아닙니다. 수신 캐시에 타임스탬프가 없고 callback도 차량 ACK로 단정하지 않습니다.

## 결과와 저장

- **후보값 ON/OFF**: DUDU 코드에 따른 `0x38 data[4] & 0x08` 해석입니다. 이번 사용자 차량에서는 OFF→ON 비트 변화와 실제 하향 동작을 함께 확인했습니다. 일반적인 상태 표시만으로 매번 실제 거울 동작을 확인한 것으로 보지는 않습니다.
- **설정 호출 시도 1회**: 설정 호출을 시도했다는 의미입니다. 거울 동작 성공 표시가 아닙니다.
- **설정 호출 시도 0회**: 조건 불일치 또는 송신 전 취소입니다.
- 응답이 지연되어도 자동 재전송하지 않습니다.
- 앱 내부 저장소에 최근 시험 보고서를 기록합니다. **이전 시험 기록 보기**로 확인할 수 있습니다. 설치 권한 요청·인터넷 권한·자동 업로드는 없습니다.

## 빌드와 검증

기존 0.2 설치 오류 수정(리소스 비압축·4바이트 정렬 보존)을 유지합니다. `python3 build.py`로 고정 해시의 도구를 사용해 빌드합니다.

기존 292개 합성 프로토콜 검사와 53개 설정 제한 검사(불일치 조건, 허용 값, 만료, 취소, 중복·동시 실행)에 통과했습니다. 최종 APK의 ZIP·리소스 정렬·서명 v1/v2·패키지·권한·내부 시험 Activity·송신 진입점을 검사했습니다. 이 수치는 호스트 환경의 검사 횟수이며 실제 차량 시험 횟수가 아닙니다. 개발 환경에서 실차를 직접 시험하지는 않았습니다. 사용자 차량에서는 0.3 설치·실행, ON 설정 후 실제 하향, 후진 해제 후 원위치 복귀가 확인됐습니다. OFF 동작과 전원 재인가 후 설정 유지는 아직 별도 확인 전입니다.

`demo-signing.p12`는 이 독립 패키지의 재빌드용 시험 키입니다. 암호는 `mirror-demo-only`이며 OEM 서명과 관련 없습니다.

## 코드 근거

DUDU 성공 APK의 `carSet(0x1E, 값)`과 `CanbusTypeRZC4.write`를 따라가면, FYT MCU 접두어를 제외한 직렬 프레임 계산은 다음과 같습니다.

```text
OFF: FD 05 80 1E 00 A3
 ON: FD 05 80 1E 01 A4
```

사용자가 첨부한 ReglinkService의 `RaisePsaDecoder.encode`에 종류 `0x80`, 데이터 `[0x1E, 값]`을 넣은 결과도 같습니다. 위 값은 코드에서 계산한 직렬 프레임이며 실차 버스 캡처나 CAN 중재 ID가 아닙니다.

미러 상태 후보는 종류 `0x38`의 순수 데이터 다섯 번째 바이트, `data[4] & 0x08`입니다. 잘못된 종류나 짧은 데이터는 OFF로 처리하지 않고 판정을 보류합니다. 실차 화면에서는 기준 CAN 박스·디코더·연결 상태를 확인한 뒤에도 ‘추정’으로 표시합니다.

공개 서버의 `26082601`, `26090708`, `26091003` 묶음 안에 있는 `model_raise_psa.js`는 바이트까지 동일합니다. 모듈 버전은 `26072201`이며 `psa_5008_2014_2019`가 포함돼 있지만 미러 토글은 없습니다. 실차에서 보고된 메뉴 묶음 버전은 `26090708`입니다. 차량 내부의 활성 스크립트 파일 바이트는 직접 읽지 않았습니다.
