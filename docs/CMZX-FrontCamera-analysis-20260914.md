# Peugeot 5008 / CMZX 순정 전방 카메라 전환 조사

조사일: 2026-09-14. 상태: 1차 자료·코드 대조 완료, 실차 원인 및 복구는 미확인.

## 사용자 증상과 조사 범위

2019 Peugeot 5008 GT에서 순정 오디오 사용 당시에는 R로 후진한 뒤 D로 바꾸면 전방 카메라 영상이 나왔다. CMZX 안드로이드 올인원 시공 후에는 R에서 후방 영상만 나오고, D 전환 뒤 전방 영상은 표시되지 않는다.

이 기록은 전방 카메라에 대한 새 조사다. 미러 프로젝트의 `CMZX-MirrorCheck-v03.apk`는 하향·원위치 복귀 성공 기준본으로 그대로 보존한다. 별도 원격시동 앱과도 구분한다.

현재 자료로 **전방 표시 기능을 추적할 구체적인 코드와 설정 항목은 확인했다.** 다만 서비스 코드에 기능이 존재하는 것과 사용자의 순정 영상 경로에서 실제로 작동하는 것은 별개이므로, 복구 성공이나 설정 하나로 해결된다고 결론 내리지는 않는다.

공식 설명서의 Visiopark 2 항목에는 앞·뒤 카메라를 사용하는 구성, 후진 시 후방 표시, 후진 해제 시 전방 영상으로 전환해 7초간 표시하는 동작이 안내돼 있다. 7초는 설명서 기준이며 사용자 차량의 실제 시간을 측정한 값은 아니다.

## 서비스 APK에서 확인한 처리

| 확인한 코드 | 내용 | 이번 증상과의 관계 |
|---|---|---|
| `SettingsObserver.loadCameraSettings()` | `camera` 설정 묶음의 `front_gear_start`를 `Env.FrontGearStart`로 읽음 | D단 전면 표시를 제어하는 설정이 실제로 존재함. 현재 차량의 값은 미확인 |
| `CameraController.onGearChanged()` | `getGear()`가 `gear_d`이고 `FrontGearStart`가 켜져 있으면 전면 표시 메시지를 보냄. `gear_p`에서는 닫기 메시지를 보냄 | 후진 감지와 별도로 D단 정보를 올인원이 받아야 이 경로가 실행됨 |
| `CameraController.onReverseChanged()` | 후진 상태가 끝나면 후방 닫기 메시지(4)를 보냄 | 이 메서드의 비후진 분기에는 전방 7초 유지 처리가 없음 |
| `CameraController.openFrontView()` / `startCamera()` | 전면 표시 요청은 `com.reglink.action.FrontCamera` 화면 실행으로 이어짐 | 순정 영상이 그 화면의 입력으로 연결되는지는 카메라 앱과 실차에서 확인해야 함 |
| `CameraController.handleMessage()` | 네이티브 카메라가 이미 표시 중이면 전면 열기 메시지 처리를 보류하는 분기가 있음 | 전환 시점·이벤트 순서를 관찰할 이유가 있음. 이번 차량에서 이 분기가 원인인지는 미확인 |
| `front_speed_start`, `front_open_speed`, `front_close_speed` | 속도에 따른 전면 표시 제어용 설정을 읽음 | 일반 D단·속도 전면 기능과 순정 R→D 전환 동작을 같은 기능으로 가정하면 안 됨 |

`front_gear_start`는 직전에 R이었는지를 이 메서드에서 검사하지 않고 D단 변경을 처리한다. 따라서 이를 켜는 것만으로 순정의 후진 해제 후 7초 표시가 재현된다고 볼 수 없다. 화면 종료 조건과 실제 영상 입력도 함께 확인해야 한다.

## 이름만 보고 적용하면 안 되는 항목

- `sys.delay_reverse`: 코드에서는 **후진 화면을 열기 전의 지연**으로 읽는다. D 전환 뒤 전면 화면을 유지하는 시간으로 해석하지 않는다.
- `ReverseExitDelayWorkAround`: 이름과 달리 분석한 구현은 카메라 영상 신호 유무를 감시해 미리보기를 닫고 다시 여는 보정이다. 이 클래스의 존재만으로 순정 전방 전환 지원을 주장할 수 없다.
- `reglink.psa.PsaCameraController`: APK에 별도의 PSA 순정 파노라마 처리 코드가 있다. 그러나 현재 사용자의 `raise-psa` 경로와 같은 구현이라고 볼 수 없다. 이 클래스의 CAN 명령을 Raise 박스에 그대로 적용할 근거는 없다.

공개 묶음의 해당 Raise PSA 모델 파일에서는 `putGear`, `putCameraRequire`, `camera_touch` 같은 전방 전환 관련 처리를 찾지 못했다. 이것은 **그 모델 파일의 정적 검색 결과**다. 공통 스크립트, 확장 서비스, MCU 등 다른 경로를 포함해 실차 D단 수신이 불가능하다고 확정한 것은 아니다.

## 남아 있는 원인 후보

1. **후진 영상 창이 R 해제와 함께 닫히는 경우**: 순정 영상은 이어질 수 있는데 올인원이 표시를 종료했는지 확인한다. 아직 영상 신호가 실제로 유지되는지는 모른다.
2. **D단 전면 표시 요청이 실행되지 않는 경우**: `front_gear_start` 값, 실차 `getGear()` 결과, 전환 시 네이티브 카메라 표시 상태를 대조한다.
3. **전면 화면은 열리지만 영상이 나오지 않는 경우**: 순정 앞·뒤 영상이 하나의 출력에서 전환되는 구성인지, 별도 전면 입력인지, 현재 배선·어댑터가 어느 입력으로 전달하는지 확인한다. 사용자의 실제 배선 방식은 아직 확인하지 않았다.

R에서 영상이 나오는 사실은 후방 영상 표시가 동작한다는 근거다. 그것만으로 전방 카메라 연결, 전원, 순정 모듈의 영상 전환 또는 CAN 지원까지 확인된 것은 아니다.

## 다음 확인과 이어갈 작업

우선 사용자에게 **R에서 D로 바꾸는 순간 카메라 창이 닫히고 홈/이전 앱으로 돌아오는지** 확인받는다. 이 관찰로 화면 종료 쪽을 먼저 볼지, 열린 화면의 영상 입력 쪽을 먼저 볼지 정한다.

이후 자료가 필요하면 서비스가 참조하는 카메라 앱 `com.reglink.apps.camera`의 설치 APK를 확보해 화면·입력 선택을 분석한다. 현재 그 APK의 설치 버전과 실제 내용은 확보하지 않았다. 카메라 설정 메뉴 사진은 표시되는 항목과 현 설정을 연결하는 데 도움이 된다.

후속 읽기 진단의 대상은 `camera` 설정 묶음, P/R/N/D에서의 기어 값과 후진 상태, 전면·후면 표시 상태, 영상 유무다. 이 정보들을 외부 일반 앱에서 모두 읽을 수 있는지는 추가 검증 대상이다. 기존 미러 진단 로그에는 이 카메라 진단 값이 들어 있지 않다.

이번에는 서비스·미러 APK·MCU·차종 설정을 변경하거나 차량으로 명령을 보내지 않았다. 전방 카메라용 새 APK도 아직 제작하지 않았다.

## 보관한 근거

`CMZX-FrontCamera-evidence-20260914.zip`에 사용자 제공 서비스 APK에서 추출한 관련 메서드, DEX 명령, 참조 검색 결과와 이 보고서를 보관했다. Java 형태의 출력은 역컴파일 분석용이며 타입 추론 오류가 있을 수 있다. D단 조건·후진 종료·전면 화면 실행 등 주요 분기는 DEX 명령과 함께 대조했다. 실행 가능한 원본 소스나 수정 APK로 취급하지 않는다.
